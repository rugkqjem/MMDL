# DPO 루프 쌍: 두 가지 만드는 방식 비교

> 2026-11-17 · 브랜치 `rl-grpo` · `scripts/dpo_pairs.py`에 두 방식 모두 구현
> 숫자는 최종 학습셋(`train_final`, 780문제) 롤아웃으로 맥에서 실측. 재샘플링 방식은 GPU 단계 전이라 **설계값과 사전 측정값만** 있음

## 한눈에 보기

| 항목 | **cut** (승희 방식, "SFT → DPO 계획 초안") | **resample** (갈림길 재샘플링) |
|---|---|---|
| 실행 | `--loop_mode cut` | `--resample outputs/dpo/resample.jsonl` |
| 필요한 것 | **CPU만. 지금 바로 가능** | RFT 체크포인트 + GPU 재샘플링 |
| chosen | 같은 문제의 **다른** 정답 응답 ("불일치 후 회복" 우선) | 같은 앞부분에서 **다시 생성해 빠져나온** 이어쓰기 |
| rejected | 루프 응답의 **처음부터**, max(chosen 길이, 첫 보기 불일치 + 1,500토큰), 최대 4,095토큰 | 갈림길 **이후** 원래 응답 (루프 텍스트 50% 이상 들어가게) |
| 공통 앞부분 | 없음 | 있음. 프롬프트로 들어가서 손실에서 상쇄 |
| 가르치는 것 | "이 문제에서는 루프 풀이 말고 이 정답 풀이" | "**이 지점에서** 반복을 끊고 결론 내기" |

## 실측 (최종 학습셋)

| 항목 | cut | resample |
|---|---|---|
| 대상 문제 | **160** (잘린 응답에 보기 불일치 표현이 있고, 정답 응답도 있는 문제) | **375** (잘린 응답이 있는 모든 문제). cut의 160문제를 전부 포함 |
| 쌍 / 후보 수 | **230쌍** (문제당 최대 2) | 재샘플링 후보 615개 응답 (문제당 최대 2). 실제 쌍 수 = 빠져나온 응답 수 (**미측정**) |
| 빠지는 것 | 첫 보기 불일치가 4,095토큰 뒤에 나오는 응답 127개 | 4개 갈림길 모두에서 못 빠져나온 응답 (미측정) |
| chosen | "불일치 후 회복" 164/230 (71%), 중앙값 4,302토큰. 6,000토큰 넘는 것 56개 | SFT 모델 출력. 남은 예산(8,192 − 앞부분) 안에서 끝난 것만. 길이 미측정 |
| rejected 길이 | 중앙값 4,068토큰(추정), chosen과 비율 1.05 | chosen 이상, 최소 2,000자 |
| **rejected 중 루프 전 정상 풀이** | 첫 보기 불일치 앞부분이 **중앙값 45%** → 이 부분도 "나쁜 응답"으로 눌림 | 갈림길 앞은 손실에 안 들어감 |
| **rejected의 반복·망설임 텍스트 비율** | **중앙값 34%** | 갈림길 60%: 74% / 45%: 65% / 30%: 54% / 15%: 45% (그 뒤 4,000토큰 기준. 실제로는 빠져나온 갈림길만 쓰임) |
| 길이 지름길 | chosen과 rejected 길이를 맞춤 (1.05) | 빠져나온 이어쓰기가 짧으면 rejected가 더 김 → 정답 쌍·sft 항·`ld_alpha`로 견제 |

참고: 같은 규칙으로 "보기 불일치 표현이 없는 잘린 응답"까지 넓히면(`--cut_scope all`) 477쌍 / 303문제.

## 각 방식의 위험

**cut**
- rejected의 약 절반이 루프 전 정상 풀이라, **멀쩡한 추론도 같이 눌릴 수 있음**. 앞서 DPO 주의점 정리에서도 지적된 문제("루프 전의 정상 풀이만 rejected로 눌리는 잡음")
- chosen이 다른 풀이 경로라서, "루프 피하기"보다 **풀이 스타일 차이**를 배울 수 있음
- 루프가 늦게 시작되는 응답(127개)은 못 씀

**resample**
- GPU 비용: 615응답 × 8번 × 최대 4라운드 (늦은 갈림길일수록 이어쓰기가 짧아 싸짐)
- 탈출률이 낮으면 쌍이 부족할 수 있음
- 빠져나온 이어쓰기가 "찍기"일 수 있음 → `--loop_chosen_correct`로 정답만 chosen
- RFT가 끝나야 시작 가능

## 공통으로 아직 안 된 것

- **E(판독 재시도)·G(정상적인 긴 계산) 제외**: 두 방식 모두 아직 미적용. 의미 밀도 4.5? 정의를 받으면 필터로 추가
- **실제 토큰 수**: cut의 토큰 수는 응답별 글자/토큰 비율로 추정. 서버에서 `train_dpo.py --check_only`가 정확한 길이를 출력

## 제안

1. **DPO v0 = 정답 쌍 531 + cut 루프 쌍 230**: RFT가 끝나면 바로 학습 가능
2. **DPO v1 = 정답 쌍 531 + resample 루프 쌍**: 재샘플링이 끝나면 학습
3. 두 모델을 같은 probe 세트(검증셋 루프 문제 × 4회)와 MMMU 루프 많은 과목으로 비교. 주 지표는 타깃 유형(A1·A2·C·D·F)의 잘림 수, 보조 지표는 끝까지 답한 문제의 정확도(일찍 찍기 확인)

```bash
python scripts/dpo_pairs.py --loop_mode cut --out outputs/dpo/pairs_cut.jsonl            # v0 데이터 (지금)
python scripts/dpo_pairs.py --resample outputs/dpo/resample.jsonl --out outputs/dpo/pairs_resample.jsonl   # v1 데이터
python scripts/train_dpo.py --model_path outputs/rft/merged --pairs outputs/dpo/pairs_cut.jsonl --output_dir outputs/dpo/v0
```
