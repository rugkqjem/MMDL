# 루프 정답지 1차 결과와 DPO 설계 변경

> 2026-11-17 · 브랜치 `rl-grpo` · 라벨링: 유진 (30개 중 17개)
> 한 줄 요약: **잘린 응답은 사실상 전부 루프였고, 루프 시작 위치는 텍스트 규칙으로 못 찾는다.** 그래서 DPO 데이터는 "잘린 응답 전부"를 대상으로 하고, 갈림길은 재샘플링으로 정하도록 바꿨다.

## 1. 왜 만들었나

DPO 루프 쌍을 만들려면 ① 어떤 응답이 루프인지 ② 루프가 어디서 시작되는지를 자동으로 찾아야 한다. 그런데 오답 분류 때 쓴 기존 루프 규칙(`classify_errors.py`: 마지막 1만 자 압축률 < 0.10 또는 반복 줄 ≥ 80%)은 MMMU 잘림의 96%를 루프로 잡았지만, ViRL 최종 학습셋 잘림에서는 **33%(1,044개 중 346개)**만 잡았다. 이 규칙이 ViRL 응답에 맞는지, 위치를 찾는 새 규칙이 쓸 만한지 사람이 직접 본 기준이 필요했다.

## 2. 데이터와 방법

- **응답**: GRPO 데이터 선별 때 돌린 롤아웃(원본 Qwen3-VL-4B, 평가 샘플링, 최대 8,192토큰) 중 **최종 학습셋(`train_final`, 780문제)** 문제의 잘린 응답 1,044개
- **뽑기**: 기존 규칙에 걸린 것 20개 + 안 걸린 것 10개, 문제당 1개, 과목이 섞이게 (`scripts/make_loop_goldset.py`, seed 0)
- **블라인드**: 라벨링 페이지에는 어느 그룹인지 표시하지 않음. 그룹 대응표(`loop_gold_key.csv`)는 라벨링 후에만 열어 비교
- **라벨**: 루프 여부, 유형(MMMU 잘림 85개 분석의 A1·A2·B·C·D·E·F·G), 반복 시작 위치(사람이 "이미 나온 내용이 다시 시작되는 첫 줄"을 클릭)
- **비교**: `python scripts/loop_onset.py --compare_gold outputs/loop_gold/loop_gold_labels.csv`

## 3. 결과 (17개)

### 루프 여부: 17개 전부 루프

| 유형 | 개수 | 기존 규칙이 잡음 | 반복 규칙(새)이 잡음 |
|---|---:|---:|---:|
| A1. "보기에 없다" 되풀이 | 1 | 1 | 1 |
| A2. 조건·그림 해석을 바꿔 다시 가정 | 6 | 2 | 3 |
| B. "정보가 부족하다" 반복 | 3 | 3 | 3 |
| C. 같은 계산 블록 반복 | 4 | 3 | 4 |
| D. 답 번복 반복 | 1 | 1 | 1 |
| E. 이미지 판독 재시도 | 2 | 2 | 2 |
| G. 루프 아님 (계산하다 한도 도달) | **0** | – | – |
| **합계** | **17** | **12** | **14** |

- 기존 규칙에 **안 걸린 그룹에서 라벨한 5개도 전부 루프**였다. 기존 규칙이 "루프 아님(긴 계산)"으로 분류한 698개 중 상당수가 실제로는 루프라는 뜻이다. 5개 중 5개라 정확한 비율은 알 수 없지만, 절반 이상일 가능성이 높다.
- 놓친 루프는 거의 **A2**다. 글자를 그대로 반복하지 않고 말을 바꿔 가며 같은 고민을 되풀이해서, 글자 반복을 보는 규칙에 안 걸린다.
- 오경보(사람은 루프가 아니라는데 규칙이 루프라고 함)는 0개였다. 다만 사람이 "루프 아님"이라고 한 응답 자체가 없어서 검증된 건 아니다.

### 반복 시작 위치: 텍스트 규칙으로는 못 찾음

| 규칙 | 찾은 수 | 사람과 차이 (중앙값) | 300자 이내 | 2,000자 이내 |
|---|---:|---:|---:|---:|
| 반복 규칙: 그 뒤 70% 이상이 반복인 첫 위치 | 14/17 | −910자 | 0 | 5 |
| 밀도 규칙: 2,000자 창의 반복+망설임 표현 ≥ 70% | 16/17 | +247자 | 4 | 9 |

- 반복 규칙은 최대 ±1만 7천 자까지 틀렸다.
- 사람이 찍은 시작점은 대부분 **"Wait — perhaps…", "Perhaps the…", "But wait —"**로 시작한다. 모델이 맴돌기 시작하는 건 글자가 실제로 반복되기 한참 전이다.
- 망설임 표현("Wait", "Perhaps", "Alternatively", "Let me re…")을 세는 밀도 규칙이 가장 나았지만, 그래도 절반 정도만 2,000자 이내였다. 망설임 표현은 정상 풀이에도 자주 나와서다.

## 4. 그래서 바꾼 것

| | 바꾸기 전 | 바꾼 후 |
|---|---|---|
| 재샘플링 대상 | 텍스트 규칙이 루프라고 한 응답 (521개) | **잘린 응답 전부** (문제당 2개 → 615개, 375문제). 규칙 결과는 기록만 |
| 갈림길 후보 | 반복 시작 위치와 그 앞 200/500/1000토큰 | **응답 길이의 60 / 45 / 30 / 15% 지점**(줄 시작) |
| 갈림길 결정 | 텍스트로 찾은 위치 | 늦은 후보부터 이어쓰기 8번 → **실제로 빠져나오는 가장 늦은 지점** |
| rejected에 루프가 들어가는지 | 반복 시작 위치 + 600자 포함 | rejected 구간의 반복+망설임 텍스트가 **50% 이상**이 될 때까지 늘림 (원래 응답 끝에서 멈춤) |

- 정답지 17개로 보면, 고정 후보 4개 중 **대부분 2~4개가 사람이 찍은 루프 시작보다 뒤(루프 안)**에 있다. 그래서 루프 쌍은 주로 "루프 도중에 끊고 결론 내기"를 가르치는 쌍이 될 것이다.
- 정답지 17개 중 1개(G01)는 루프가 응답의 62% 지점에서 시작돼서, 후보가 모두 루프 앞에 있다. 이런 경우에는 "루프로 빠지기 전에 다른 길로 가기" 쌍이 된다.
- 위치를 찾는 일은 텍스트 규칙 대신 **모델이 실제로 빠져나오는지**로 판단하니, 위치 규칙의 정확도는 더 이상 결과를 좌우하지 않는다.

## 5. 남은 것

- **남은 라벨 13개**: 필수 아님. G(루프 아님)가 실제로 있는지 확인하는 정도의 의미. 지금 설계에서는 G가 섞여도 "한도 안에 못 끝냄"이라 rejected 자격이 있다.
- **재샘플링 결과로 확인할 것** (RFT 체크포인트로 GPU에서 실행)
  - 후보별 탈출률. 60% 지점에서 대부분 빠져나오는지, 앞 후보까지 가야 하는지
  - 탈출한 이어쓰기가 A1·A2에서 "가장 가까운 보기로 결론"을 내는지. MMMU 잘림 분석에서 A1·A2 36개 전부에 보기 불일치 표현이 있었다
  - rejected의 반복 비율 50%를 못 채우고 원래 응답 끝까지 간 쌍의 비율. 가짜 데이터 80개로는 23개가 이랬다(글자 반복이 적은 A2형으로 보임)
